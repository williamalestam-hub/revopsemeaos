## Ids (the doc id IS the dedupe key)

gr-<meetingId>-<slug40> Granola next step (slug of the task text) · gm-<threadId> Gmail thread · sl-<channelId>-<ts with . as _> Slack message · cal-<eventId>-<YYYY-MM-DD> calendar event (meeting prep) · ins-<metric>-<YYYY-MM-DD> insight · esc-<sourceId> escalation · man-<random> (both page only). slug40: lowercase, strip accents, every run of characters other than a-z 0-9 becomes `-`, trim `-`, cut to 40 — computed only with `python3 -c 'import sys,re,unicodedata as u;s=u.normalize("NFD",sys.argv[1].lower());s=re.sub("[\u0300-\u036f]","",s);print(re.sub("[^a-z0-9]+","-",s).strip("-")[:40])' "$t"` (t = the task text), never by hand. Any character outside letters, digits and `_ - . ~ : @ +` in a source id becomes `_`. ## Writing

All item writes go in ArtifactData `batch` calls of ≤ 50 `writes` ({op: set|update, collection, doc_id, data, if_version}): `set` without if_version only for an id no read returned; `update` with the `version` you read for an existing one; each document at most once per batch. Before the first batch, read every candidate id that step 0 did not load (`query` items with where [["id", "in", [...]]] in groups of ≤ 30, or `get` each): an id that exists with a status other than new, prepared or waiting, or with a log entry whose `by` is not 'worker', is skipped (counted in skipped), never set again. On a refused or conflicting write, re-read that document once: if it now exists with such a status or log entry, drop the write and count it as skipped; otherwise redo it with the new `version`.

## Drafting
